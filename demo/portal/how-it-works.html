How it works कैसे

Three checks, one log, one outside witness.

VICT doesn't ask your developers to remember rules. It puts the rules in the only path borrower data can take out of your servers, and writes down every decision where your NBFC partner can check it.

1

Ask before you send

Before calling a bureau, AA or KYC provider, your code asks the consent authority for a token. The authority checks the borrower's consent for this lender and this purpose. If it's missing, withdrawn or expired, no token is issued and nothing touches the network.

  • Consent is keyed on lender, borrower and purpose together.
  • A token lives 60 seconds and names the exact hosts it may reach.
  • The app carries the token but can't create one: only the authority holds the signing key.

2

Show the token at the gate

The call goes through VICT's egress proxy as an ordinary HTTPS CONNECT. The proxy checks the token's signature and expiry, that the destination is on your vendor list and named in the token, that the port is 443, and that consent is still valid right now. Then it opens a tunnel and steps aside.

  • It never decrypts TLS, so bureau client certificates and signed AA payloads pass through untouched.
  • Raw IP addresses and plain HTTP are refused.
  • When the borrower withdraws, open tunnels for that consent are cut within a second.

3

Leave no other way out

An SDK that ignores the proxy should find nothing on the other side. A Terraform module gives app subnets three independent layers: a route table with no internet gateway or NAT, a network ACL that only allows traffic inside the VPC, and security groups that only reach the proxy.

  • Each layer holds on its own, so one permissive security group doesn't reopen a path.
  • The proxy gets one fixed IP, which bureaus and AAs can put on their own allow-lists.
  • Route tables, ACLs and security groups cost nothing in AWS.
infra/terraform · egress_lockdown
module "egress_lockdown" {
  source                = "./modules/egress_lockdown"
  vpc_id                = aws_vpc.lsp.id
  app_subnet_ids        = [aws_subnet.app_a.id,
                           aws_subnet.app_b.id]
  internal_egress_cidrs = ["10.0.5.0/24"] # database
}
4

Write it down where the NBFC can check

Every token issued or refused, every tunnel opened, blocked or cut, goes into a hash-chained ledger. Each entry's hash covers the one before it. The LSP signs the latest head with an Ed25519 key, and the NBFC's witness pulls it every few seconds.

  • The witness checks that each new head extends the one it already holds.
  • It works from 32-byte digests, so no borrower data reaches the NBFC.
  • Rewrite, delete or fork history and the alarm stays raised until someone investigates.

For your developers

One with block per vendor call.

The SDK opens one consented session per borrower, purpose and call. Each session gets its own token and connection pool, so a pooled connection can never carry another borrower's request.

Python today. Any HTTP client that supports an HTTPS proxy can use the gateway once the consent authority runs as its own service; that's next on the roadmap.

from src.egress.sdk import VictEgress, EgressBlocked
from src.egress.consent import ConsentDenied

vict = VictEgress(issuer=authority, lsp_id="lsp-acme",
                  proxy_url="http://vict-proxy:3128")

try:
    with vict.session(principal_id="borrower-001",
                      purpose="loan-eligibility",
                      hosts=["bureau.example.in"]) as s:
        score = s.post("https://bureau.example.in/score",
                       json=payload, cert=client_cert)
except ConsentDenied as e:   # nothing was sent
    log.info("blocked before network: %s", e.reason)
except EgressBlocked as e:   # nothing reached the host
    log.warning("blocked at proxy: %s", e.reason)

Design decision

Why an explicit proxy, not eBPF or a sidecar?

A transparent interceptor only sees the destination and encrypted bytes. It has no consent token, so it can't tell one borrower's call from another's.

Seeing more would mean decrypting TLS, which breaks the client certificates and signed payloads that bureaus and Account Aggregators require.

An explicit proxy keeps per-call consent and end-to-end encryption. The network lockdown removes the bypass that an explicit proxy would otherwise leave open.

Known gap: DNS. AWS security groups don't filter queries to the Amazon resolver, so compromised code could leak a little data through DNS lookups. Route 53 Resolver DNS Firewall closes it; it's a paid AWS service.
